# Sub2API 连接自动同步与全量导入设计

- 日期：2026-09-08
- 状态：待规格确认
- 目标分支：`feat/high-performance-scheduler`

## 1. 背景与目标

当前设置页的 Sub2API 连接只支持人工操作：管理员手动点击“同步”，读取远端账号后再全选或逐个选择导入。连接数量或远端账号数量增加后，需要持续人工维护，容易遗漏新账号。

本设计为每个 Sub2API 连接增加独立的自动同步配置，自动读取连接范围内的全部 OpenAI OAuth 账号并导入本地账号池。目标是：

- 每个连接独立配置同步周期；
- 启用或修改配置后立即执行一次，随后按周期执行；
- 同一连接的自动同步、手动导入互斥，避免重复请求和数据竞争；
- 远端删除账号不影响本地账号，只做新增和刷新；
- 一个连接失败不阻塞其他连接；
- 不产生无界等待队列，避免连接数增加后内存和线程持续增长；
- 通过设置页查看运行状态、上次结果、失败原因和下次执行时间。

## 2. 已确认规则

### 2.1 周期配置

- `0` 表示关闭自动同步；
- 正整数 `x` 表示每 `x` 分钟执行一次；
- 不接受负数、小数或空值；
- 新连接默认关闭，避免保存连接后立即产生远端请求；
- 新建连接时直接配置正整数，或者将已有连接从 `0` 改为正整数，保存后立即执行一次；
- 已启用连接修改同步周期、地址、认证信息或分组范围并保存后，立即执行一次；仅修改显示名称不触发额外同步；
- 关闭自动同步后不再启动新的周期任务；已经开始的远端请求允许结束，结束后不再安排下一次任务。

### 2.2 同步范围与本地写入

- 每次自动同步调用现有远端账号分页接口，读取连接配置范围内的全部 OpenAI OAuth 账号；
- `group_id` 为空时读取全部 OpenAI OAuth 账号，配置分组时只读取该分组内的账号；
- 自动同步不提供选择列表，读取到的全部远端账号都进入导入流程；
- 只新增本地不存在的账号并刷新已有账号；
- 远端账号被删除、移出分组或暂时不可见时，不删除本地账号，也不禁用本地账号；
- 远端没有账号时视为一次成功同步，不能把本地账号清空；
- 远端列表分页和凭据导出需要分批处理，避免大量账号拼接成超长请求，同时在一个自动同步任务中汇总结果。

## 3. 总体方案

采用当前应用进程内的后台调度器，不新增第三方调度依赖：

```text
设置页保存连接
       |
       v
Sub2APIConfig 持久化 interval + 状态
       |
       +--> auto-sync scheduler 唤醒
                    |
                    +--> 到期连接尝试获得连接锁
                    |          |
                    |          +--> 获取远端全部账号
                    |          +--> 导入并刷新本地账号
                    |          +--> 写入结果和下次执行时间
                    |
                    +--> 其他连接可并行执行
```

调度器由一个协调线程和有界的同步执行池组成：

- 协调线程只负责计算到期连接、唤醒和派发，不执行网络请求；
- 每个连接最多有一个活动同步任务；
- 执行池使用固定上限，连接数增加不会创建同等数量的常驻线程；
- 执行池已满时不排队，当前周期记为跳过并安排下一周期；
- 同一连接的周期任务不会堆积，错过多个周期也只保留下一次执行机会；
- 不同连接可以并行执行，不因单个慢连接串行阻塞全部连接。

该方案适合当前单进程部署方式。若未来使用多个 Uvicorn/Gunicorn worker，每个进程都会拥有自己的调度器，需要增加 SQLite 租约或改用外部调度服务；本次不扩大到多进程协调。

## 4. 持久化数据设计

继续使用现有 `data/sub2api_config.json`，不新增数据库表。每个连接增加以下字段：

```json
{
  "auto_sync_interval_minutes": 0,
  "auto_sync": {
    "status": "disabled",
    "last_started_at": null,
    "last_finished_at": null,
    "last_success_at": null,
    "next_run_at": null,
    "last_error": "",
    "last_remote_count": 0,
    "last_import_job_id": "",
    "last_import_failed": 0
  }
}
```

字段语义：

- `auto_sync_interval_minutes`：管理员配置的周期；
- `status`：`disabled`、`idle`、`running`、`completed` 或 `failed`；
- `last_started_at`、`last_finished_at`、`last_success_at`、`next_run_at`：UTC ISO 8601 时间；
- `last_error`：最近一次列表、导出或本地导入失败原因；
- `last_remote_count`：最近一次成功读取到的远端账号数；
- `last_import_job_id`：最近一次自动导入任务的 ID，用于关联现有导入进度；
- `last_import_failed`：最近一次导入中失败的账号数。

旧配置文件没有这些字段时按关闭状态加载。运行中的状态变化通过现有配置锁持久化，API 返回和后台线程读取使用同一份规范化结构。敏感字段 `password` 和 `api_key` 继续只保存在服务端，不能出现在 API 响应或自动同步状态中。

### 4.1 重启恢复

- 配置为 `0` 的连接恢复为 `disabled`；
- 配置为正数且 `next_run_at` 在未来时，按照该时间继续等待；
- 配置为正数但没有有效 `next_run_at`，或者 `next_run_at` 已过期，启动后立即安排一次；
- 进程异常退出前处于 `running` 的状态恢复为 `failed`，保留“进程重启中断”的错误，并安排下一周期重试；
- 现有 `import_job` 的 `pending` 或 `running` 状态继续按当前逻辑在加载时标记为失败，自动同步不会把它当作已成功。

## 5. 同步生命周期与并发控制

### 5.1 自动任务流程

一次自动同步执行以下步骤：

1. 调度器确认连接仍存在、周期大于 `0`，并尝试获取该连接的非阻塞操作锁；
2. 获取失败时说明手动导入或上一次自动同步仍在运行，本周期跳过，不创建排队任务；
3. 获取远端账号完整列表并提取全部远端 ID；
4. 远端列表成功后，按受控批次导出凭据并启动现有导入服务；
5. 等待该导入任务进入终态；
6. 导入完成且没有账号级错误时标记本次同步成功；
7. 导入部分失败、远端列表失败、凭据导出失败或本地写入异常时标记失败，保留错误信息；
8. 成功或失败都释放连接锁，并把下一次执行时间设置为当前时间加配置周期。

没有远端账号时跳过导入任务，但仍完成第 6 步。自动同步失败不会删除或回滚本次已经成功写入的本地账号，下一周期重新读取并重试。

### 5.2 手动导入与自动同步互斥

现有手动导入服务和自动同步服务共享同一个按连接划分的锁：

- 手动导入开始前尝试获得锁；锁被占用时返回 HTTP `409`，提示该连接已有导入任务；
- 自动同步在读取远端列表前就获得锁，避免读取期间手动导入插入；
- 导入线程结束或异常时必须释放锁；
- 锁只在进程内保护并发，状态字段用于重启后的诊断和恢复，不把 JSON 文件锁当作跨进程互斥。

如果上一次自动同步仍在运行，下一次到期检查直接跳过，保持当前失败信息和最近结果不变，并在下一个周期再次尝试。跳过不会立即重试，也不会产生新的等待队列。

### 5.3 状态与错误保留

- 开始任务时状态为 `running`，更新 `last_started_at`；
- 成功时状态为 `completed`，清空 `last_error`，更新成功时间、远端数量、导入统计和 `next_run_at`；
- 失败时状态为 `failed`，写入可读错误和 `next_run_at`；
- 因锁占用或执行池满而跳过时，不清空已有 `last_error`，也不伪造成功状态；
- 下一次真正开始执行时再切换为 `running`；成功后才清除旧错误。

导入服务本身需要保证异常也能把任务标记为失败并释放锁，不能因后台线程异常退出而永久停留在 `running`。

## 6. 后端 API 与服务边界

### 6.1 配置 API

扩展现有请求模型：

- `POST /api/sub2api/servers` 增加 `auto_sync_interval_minutes`，默认 `0`；
- `POST /api/sub2api/servers/{server_id}` 增加可选的 `auto_sync_interval_minutes`；
- `GET`、`POST` 响应中的连接对象返回周期和 `auto_sync` 状态摘要；
- 创建或更新完成后通知自动同步服务重新读取配置；满足立即条件时唤醒调度器；
- 删除连接时取消其后续调度。已经开始的网络操作不强制中断，但删除后不得再安排新的任务或写回不存在的连接。

不新增独立的手动触发 API。设置页保存配置即可触发立即同步，已有导入进度查询接口继续用于人工导入进度。

### 6.2 手动导入 API

`POST /api/sub2api/servers/{server_id}/import` 保留原请求格式。连接锁被占用时返回：

```json
{
  "detail": {
    "error": "该连接已有同步任务正在运行",
    "code": "sub2api_sync_busy"
  }
}
```

HTTP 状态为 `409`。参数为空仍返回 `400`，连接不存在仍返回 `404`。

### 6.3 服务职责

- `Sub2APIConfig`：规范化、读取和保存连接配置及状态；
- `Sub2APIImportService`：负责单次账号凭据导出、添加和刷新，并提供共享连接锁、忙碌判断和终态查询；
- `Sub2APIAutoSyncService`：负责周期计算、立即唤醒、有限并发、自动任务生命周期和状态更新；
- API 层：鉴权、参数校验、状态码映射，不执行同步网络请求；
- `api.app` lifespan：启动和停止自动同步服务。

## 7. Web 设置页

### 7.1 配置表单

在新增和编辑连接表单中增加数字输入：

- 标签：`自动同步间隔（分钟）`；
- 最小值：`0`；
- 只允许整数；
- `0` 显示为关闭；
- 正数显示启用提示；
- 编辑已有连接时回填服务端配置。

保存成功后沿用现有连接列表更新，不要求管理员刷新页面。

### 7.2 连接卡片状态

每个连接显示：

- 自动同步开关状态和周期；
- 当前状态；
- 上次执行时间和远端账号数；
- 下次执行时间；
- 最近错误摘要；
- 自动导入任务的新增、跳过、刷新、失败统计。

页面沿用现有轮询机制，在任一连接的自动同步或导入任务处于 `pending`、`running` 时轮询连接列表；没有活动任务时停止轮询。轮询只读取汇总状态，不拉取远端账号列表，避免页面刷新造成额外 Sub2API 请求。

手动“同步”入口仍保留，用于查看远端账号和选择性导入。自动任务运行期间点击手动导入时，前端展示后端 `409` 错误，不自动反复提交。

## 8. 可观测性与日志

自动同步不按账号输出日志。每次任务只记录必要的结构化事件：

- `sub2api_auto_sync_started`：连接 ID、周期和任务 ID；
- `sub2api_auto_sync_completed`：连接 ID、远端总数、导入统计和耗时；
- `sub2api_auto_sync_failed`：连接 ID、阶段、错误摘要和下次时间；
- `sub2api_auto_sync_skipped`：连接 ID、跳过原因。

凭据、密码、API Key、access token 不写入日志。账号级错误聚合到持久化任务状态，限制保存数量，避免单次异常产生大量日志或无限增长的错误数组。

## 9. 测试范围

### 9.1 服务层测试

- 旧配置加载时自动同步字段默认为关闭；
- 周期值 `0`、正整数、负数、小数和非法值的规范化行为；
- 配置保存后字段和状态可恢复；
- 启动时未来 `next_run_at` 不提前执行，过期时间会安排执行；
- 启用或同步相关配置修改会立即触发一次；关闭后不触发新任务；
- 自动同步读取全部分页账号并将全部 ID 交给导入流程；
- 大量账号按批次导出，不生成超长请求；
- 远端列表为空时成功且不删除本地账号；
- 远端删除账号时本地账号仍存在；
- 列表、导出、本地导入失败时状态为 `failed`，错误保留且下一周期可重试；
- 自动任务运行时手动导入返回忙碌，手动导入运行时自动周期跳过；
- 同一连接不会同时存在两个自动任务，不同连接可以并行；
- 导入线程异常时任务不会永久停留在 `running`，锁会释放；
- 删除连接后不会继续写回状态。

### 9.2 API 与前端测试

- 创建和更新 API 接受并返回同步配置；
- 非管理员不能修改自动同步配置；
- 手动导入占用时 API 返回 `409`；
- 设置页可新增、编辑、关闭和查看周期状态；
- 正在运行时页面能看到状态，结束后停止轮询；
- TypeScript 检查、ESLint 和生产构建通过。

## 10. 验收标准

1. 管理员为某个连接设置 `5` 分钟并保存后，该连接立即进行一次全量同步，之后每 5 分钟执行一次。
2. 自动同步读取到的所有远端 OpenAI OAuth 账号都会进入导入流程，不需要再点“全选”或逐项选择。
3. 本地账号只新增和刷新，不因远端账号删除而被删除或禁用。
4. 自动同步运行超过一个周期时不会并发启动同连接的第二个任务，也不会产生无限等待队列；下个周期会重试。
5. 自动同步失败时设置页保留失败状态和原因，下一周期能够再次执行。
6. 手动导入与自动同步不会同时修改同一个连接的本地导入流程。
7. 服务重启后，已启用连接能够根据持久化的下次时间继续执行，异常中断任务不会永久显示为运行中。
8. 任意连接的同步失败不会阻塞其他连接的自动同步。
