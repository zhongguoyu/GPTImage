# 运行时内存优化与统一 SQLite 状态设计

## 状态

已确认设计，实施分支：`feat/memory-optimization-sqlite`。

基线分支：`feat/high-performance-scheduler`。

## 目标

在不降低文本、图片生成和图片编辑吞吐量的前提下，降低进程启动后及长期运行过程中的 RSS、Python heap 和原生内存峰值，并消除状态数据通过 JSON 全量读写带来的 I/O、解析和内存放大。

本次改造覆盖：

- P0/P1 内存优化方案全部落地；
- 账号、任务、额度和用户密钥迁移到统一的 SQLite 数据库；
- 保留管理员密钥现有配置/环境变量来源，不写入用户密钥表；
- 保留旧数据文件作为可回滚副本，迁移可重复执行且具备校验；
- 不改变现有调度并发上限和同步上游调用语义。

## 非目标

- 不在本次改造中拆分服务或引入 Redis、PostgreSQL 等外部依赖；
- 不改变文本、图片生成、图片编辑的业务额度扣减语义；
- 不把日志写入统一状态库。高频日志继续独立使用 `logs.db`，避免日志写入阻塞账号、任务和额度事务；
- 不删除旧 JSON/SQLite 文件，回滚前由运维显式切换后端。

## 当前问题

### 高收益内存来源

1. `AccountPool` 的能力堆在账号租约发布/撤销后只做惰性清理，旧堆项长期积累。账号少时不明显，长期高频请求后会线性增长。
2. 账号刷新和重新登录进度结果保存在类级字典中，完成结果包含完整账号快照，且没有统一 TTL 清理。
3. 轮换 token 的别名只在删除账号时清理，没有按时间或数量上限清理。
4. 对话缓存只有条目数上限，没有字节上限；单个大响应或流式响应可以长期占用较多 heap。
5. 图片输入、Codex/SSE 响应和图片编辑流程存在整包读取、`list` 聚合、重复 Base64 和重复 Pillow 合成，造成瞬时 RSS 峰值。
6. 可编辑文件任务为每个提交创建原生线程，任务参数直接携带完整 Base64，且历史任务无可靠上限。
7. SQLite 日志及状态服务使用多个线程连接，各连接自带 page cache；部分可选后端在启动时被无条件导入。

### 数据层问题

- 默认账号和用户密钥使用 JSON 文件，更新一个账号可能触发全量序列化和写盘；读取时也需要把整个文件解析成 Python 对象。
- 调度任务、额度、账号和用户密钥分散在多个文件/数据库，启动恢复和后台清理需要多次扫描。
- 任务结果可能把不适合持久化的临时数据与状态混在一起，增加长期存储和恢复时的对象数量。

## 目标架构

### 数据库边界

使用两个 SQLite 文件：

- `data/app.db`：账号、用户密钥、任务、额度、预约、调度健康状态；
- `data/logs.db`：必要业务日志和审计日志。

两个库都启用 WAL、忙等待和有限 page cache。日志库独立存在，避免日志保留/查询对核心状态事务产生锁竞争。

### 统一状态表

`app.db` 至少包含以下表：

- `schema_migrations`：迁移版本、来源指纹、完成时间和校验摘要；
- `accounts`：账号身份、token、状态、代理、错误计数、时间戳等热字段；未知低频字段进入受控的 `extra_json`，不再用完整账号 JSON 作为唯一存储；
- `account_limits`：按账号和能力保存额度/重置时间；
- `account_token_aliases`：轮换 token 的别名、过期时间和最后使用时间；
- `auth_keys`：用户密钥、启用状态、Web 登录权限、创建/使用时间和额度关联信息；
- `tasks`：图片生成、图片编辑和可编辑文件任务的统一状态、类型、进度、结果元数据、错误信息及时间字段；不持久化 Base64 图片内容；
- `key_quotas`：文本额度、图片额度和已用计数；
- `quota_reservations`：额度预约/结算状态，支持成功扣减、失败释放和过期回收；
- `scheduler_account_health`：调度器账号健康状态和冷却信息。

账号、任务和额度的常用过滤字段建立索引；大字段仅在详情查询时读取。服务层保留现有字典接口的兼容适配，内部写操作改为按行/按字段更新。

### 一致性边界

- 用户密钥、额度和额度预约在同一个 `app.db` 事务中完成；
- 账号变更、token 别名和账号能力额度在同一事务中更新；
- 任务状态更新与结果元数据写入同一事务；
- 日志不参与核心事务，日志写入失败不回滚业务请求；
- 迁移使用单事务，校验失败整体回滚。

## 迁移策略

迁移入口为可重复执行的 SQLite migration coordinator，并提供独立 CLI 校验入口。

来源包括：

- `accounts.json`；
- `auth_keys.json`；
- 现有 scheduler SQLite 表；
- 现有 quota SQLite 表；
- 可编辑文件任务历史（如果存在）。

执行顺序：

1. 创建新表、索引和迁移元数据表；
2. 在事务中导入并规范化来源数据；
3. 校验账号、用户密钥、任务、额度和预约记录数量，以及关键主键/密钥字段；
4. 写入迁移版本和来源指纹后提交；
5. 提交后保留所有旧文件，不自动删除或覆盖；
6. 后续启动只读取 `app.db`，除非显式选择旧 JSON 后端。

迁移失败时回滚新库事务并阻止切换到不完整数据。重复执行不会产生重复账号、任务、密钥或额度记录。管理员密钥不迁移，仍从当前配置/环境变量读取，因此现有管理员密钥保持不变。

## P0 优化

### 1. 能力堆定期压缩

在 `AccountPool` 中加入按 stale/live 比例和绝对长度触发的重建逻辑。重建只保留当前 revision、当前能力仍可用且未租约的账号；正常请求路径不做线性删除。

预期：长期高频租约场景下堆项数量回到账号规模，避免 RSS 随请求次数增长。请求路径仍保持堆操作复杂度，压缩成本摊销到后台/阈值触发。

### 2. 进度结果和 token 别名有界化

- 完成的刷新/重新登录进度结果只保留摘要和有限条目，按 TTL 清理；
- token 别名增加过期时间、每账号数量上限和后台清理；
- 清理逻辑同时覆盖成功、失败和取消状态。

### 3. 对话缓存增加字节预算

缓存同时受条目数、TTL 和进程级字节预算限制。超出预算的单个响应不进入持久缓存；大图片、工具调用和超长流默认绕过缓存。流式缓存超过预算时只保留当前请求所需的短生命周期数据，并在请求结束后释放。

默认字节预算可配置，初始值为 32 MiB，不改变现有小型文本缓存命中行为。

### 4. 图片输入预算

统一统计上传、Base64 和 URL 下载后的原始图片字节，单请求设置高但有界的总预算，默认 128 MiB；超过预算在进入上游前返回明确的 4xx。保留当前单图限制，并避免同一请求在多个阶段重复复制完整 bytes。

### 5. 图片响应改为增量解析

Codex/SSE 响应按事件读取和解析，只保留当前事件及必要的结果元数据，不再先读完整响应、构造完整 event 列表再处理。图片输出按可消费顺序交给现有同步/流式协议适配层。

## P1 优化

### 1. 图片编辑单次合成

请求构建阶段完成一次 mask 合成，并把必要的 token 统计传递给输出格式化阶段；输出阶段不再次合成。原始输入在请求对象构建完成后尽早释放。

### 2. 可编辑文件任务有界执行

使用固定大小、可观测且有界的 executor，提交入口通过有界 admission 控制，避免每个任务创建线程。排队任务使用磁盘 spool/临时文件保存大 Base64 输入，worker 完成后删除临时文件；任务状态只保留结果 URL、错误和进度摘要。

### 3. 任务保留和恢复窗口

统一任务表按终态 TTL 和最大记录数清理；启动恢复只查询可恢复状态，不把全部历史任务加载到 heap。清理和恢复均支持索引查询。

### 4. SQLite 连接和写入策略

为日志库使用受控连接/写入锁，统一设置 WAL、busy timeout、有限 page cache 和 checkpoint 参数；应用退出时显式关闭连接。核心状态库复用同一数据库文件，避免重复数据库副本，并对连接缓存设置上限。

### 5. 可选依赖懒加载与外部客户端释放

存储后端按配置懒加载 SQLAlchemy/Git 依赖；WebDAV 会话在每个操作或同步生命周期结束后显式关闭，避免连接对象和响应缓冲区长期存活。

### 6. 备份和压缩路径降峰

备份仍保持功能不变，但调整为临时文件/流式写入，避免同时驻留完整 archive、`getvalue()` 副本和加密副本。该优化不改变备份内容。

## 配置兼容

保留现有并发配置：文本 128、图片生成 32、图片编辑 32。不会通过降低 worker 上限来伪装内存优化。新增配置均提供默认值，并支持环境变量覆盖，包括统一数据库路径、缓存字节预算、图片输入预算、进度/别名 TTL、任务保留上限和文件任务最大并发。

旧 JSON 后端保留为显式回滚选项。默认运行路径切换到 SQLite；首次启动自动完成幂等迁移。管理员密钥配置名、读取方式和权限语义不变。

## 测试与验收

### 功能

- 新建、更新、删除、重启后恢复账号和用户密钥；
- 文本额度、图片额度预约/成功扣减/失败释放/过期回收；
- 图片生成、图片编辑、PPT/PSD 任务状态和结果查询；
- 迁移前后记录数量、关键字段和权限语义一致；
- 迁移重复执行不产生重复记录，失败时新库事务回滚；
- 管理员密钥仍可用，且不出现在 `auth_keys` 表。

### 内存与性能

- 长时间反复 acquire/release 后，能力堆规模不随请求次数线性增长；
- 缓存常驻字节数不超过配置预算；
- 大图片/大 SSE 响应峰值不再同时保留完整输入、完整原始响应和完整 event 列表；
- 任务提交超过 admission 上限时有界排队或明确拒绝，不创建无限线程；
- 迁移后账号更新不写入 `accounts.json`，查询使用索引和分页；
- 在相同调度并发和上游延迟下，目标路径响应时间、吞吐和 CPU 无明显回归。

### 回滚

保留旧数据文件和旧后端实现。若生产验证失败，停止服务并显式切回 JSON/旧数据库后端；新 SQLite 文件不覆盖旧来源，因此回滚不依赖删除数据。回滚前需导出迁移期间新增/变更记录，避免丢失新写入。
