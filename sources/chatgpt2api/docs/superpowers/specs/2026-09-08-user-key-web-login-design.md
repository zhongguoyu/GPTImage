# 用户密钥 Web 登录权限设计

状态：待用户审阅

## 1. 背景

当前通过 Web 管理界面生成的用户密钥，只要密钥本身处于启用状态，就可以登录 Web。现有密钥模型只有一个 `enabled` 字段，无法把“允许调用 API”和“允许登录 Web”分开控制。

需求是为每个用户密钥增加可编辑的 Web 登录权限，同时保持现有 API 鉴权行为兼容。

## 2. 目标与非目标

### 目标

- 为每个用户密钥增加独立的 `web_login_enabled` 布尔字段。
- 管理员可以在 Web 设置页查看并编辑该字段。
- 禁止 Web 登录时，仅阻止该用户密钥用于普通用户 Web 登录。
- 保持现有 `enabled` 的全局禁用语义：密钥禁用后，API 和 Web 都不能使用。
- 现有数据和现有用户密钥升级后默认允许 Web 登录，不产生意外锁定。
- 管理员密钥继续不受用户密钥 Web 登录开关影响。

### 非目标

- 不增加按接口、模型、IP 或设备维度的权限控制。
- 不改变文本额度、图片额度和调度器行为。
- 不增加用户密钥的创建向导字段；新建用户密钥统一默认允许 Web 登录，创建后可在编辑入口调整。

## 3. 权限语义

| 密钥类型 | `enabled` | `web_login_enabled` | API 调用 | Web 登录 |
| --- | --- | --- | --- | --- |
| 用户密钥 | `true` | `true` | 允许 | 允许 |
| 用户密钥 | `true` | `false` | 允许 | 拒绝 |
| 用户密钥 | `false` | 任意 | 拒绝 | 拒绝 |
| 管理员密钥 | 任意 | 不适用 | 按现有管理员逻辑 | 允许 |

`web_login_enabled` 只对 `role=user` 生效。管理员角色以及兼容旧配置的管理员密钥不读取该字段。

## 4. 数据模型与兼容性

用户密钥记录增加：

```json
{
  "web_login_enabled": true
}
```

后端读取记录时，对缺少该字段的旧数据按 `true` 归一化。创建用户密钥时显式写入 `true`。公开返回的密钥信息、列表接口和编辑接口都包含该字段；密钥原文仍只在创建成功响应中返回一次。

不新增数据库迁移脚本。当前认证存储使用已有存储后端，采用读时默认值和后续写入补齐的方式兼容历史记录，避免部署时因数据结构版本不一致导致旧密钥不可用。

## 5. 后端认证设计

### 5.1 认证路径分离

现有通用 `authenticate` 保持原语义，继续用于 API 请求：

- 校验密钥格式和哈希。
- 校验 `enabled`。
- 更新 `last_used_at`。
- 对用户密钥不额外检查 `web_login_enabled`。

新增面向 Web 登录的认证入口 `authenticate_web_login`，复用通用认证逻辑后增加用户角色检查：

- 管理员身份直接通过。
- 用户密钥在 `web_login_enabled=false` 时拒绝。
- 用户密钥在 `enabled=false` 时仍按通用逻辑拒绝。

这样可以把权限限制严格放在 `/auth/login`，不会误伤已有 API 路由或服务间调用。

### 5.2 API 层

- `api/support.py` 保留现有 `require_identity`，供 API 鉴权继续使用。
- 增加只供 Web 登录使用的身份校验入口，沿用现有 Bearer 提取、兼容管理员配置密钥和 401 错误格式。
- `api/system.py` 的 `/auth/login` 改用 Web 登录校验入口。
- `api/accounts.py` 的用户密钥更新请求增加可选字段 `web_login_enabled`，更新时只修改用户密钥记录的该字段。
- 用户密钥列表、查询以及更新成功响应公开 `web_login_enabled`，让前端可以实时展示状态。
- 管理员更新接口不暴露或处理该字段，避免产生管理员密钥的伪开关。

Web 登录被禁止时返回现有的无效密钥 401 响应，不泄露“密钥存在但权限被关闭”等内部状态。

## 6. Web 设置页设计

在设置页的用户密钥列表中：

- 每一行继续展示现有的全局启用状态。
- 增加明确的“允许 Web 登录”或“禁止 Web 登录”状态标识，不能只依赖颜色区分。
- 在现有编辑用户密钥对话框中增加二态开关，默认值取当前密钥的 `web_login_enabled`。
- 保存时与名称、额度等字段一起提交；关闭开关不会改变全局 `enabled`，反之亦然。
- 保存成功后刷新列表或更新本地状态，使开关和状态标识立即一致。
- 编辑失败时保留对话框和用户输入，并显示现有错误提示机制。

文案需明确区分：全局启用状态控制 API 和 Web，Web 登录开关只控制是否能进入 Web。

## 7. 会话行为

- 已登录用户在服务端关闭 Web 登录权限后，已有 Web 会话不会通过新增字段主动广播失效。
- 浏览器后续触发登录校验或重新登录时，服务器返回 401，前端按现有失效会话流程退出到登录页。
- 只要 `enabled=true`，该密钥已有的 API 请求不受 Web 登录开关影响。
- 重新打开 Web 登录权限后，无需重新生成密钥即可重新登录。

## 8. 测试与验收

### 后端

- 旧记录缺少 `web_login_enabled` 时归一化为 `true`。
- 创建用户密钥默认写入 `web_login_enabled=true`。
- 用户密钥 `web_login_enabled=false` 时，Web 登录认证失败。
- 同一个密钥在 `enabled=true` 时，通用 API 认证仍成功。
- `enabled=false` 时，Web 和 API 都失败。
- 管理员密钥不受用户密钥字段影响。
- 用户密钥列表和更新接口能够读写该字段，并保持既有字段和额度行为不变。

### 前端

- 类型定义包含该字段。
- 列表正确显示允许/禁止状态。
- 编辑对话框能够加载、修改并保存开关。
- 保存后再次打开编辑对话框，显示服务端保存的值。
- `tsc`、lint 和现有前端构建通过。

### 手工验收

1. 创建一个用户密钥，确认默认允许 Web 登录。
2. 在设置页关闭该密钥的 Web 登录开关，确认状态立即更新。
3. 用该密钥访问 `/auth/login`，确认返回 401。
4. 用同一个仍处于启用状态的密钥调用 API，确认仍可正常鉴权。
5. 重新打开 Web 登录开关，确认可以再次登录。
6. 用管理员密钥验证管理员登录不受影响。

## 9. 发布与回滚

本次变更只增加字段和 Web 登录判断，不改变旧数据的默认行为。发布后先验证旧密钥登录和 API 调用，再验证关闭/打开开关的完整流程。

如需回滚应用代码，旧版本会忽略新增字段并继续按 `enabled` 认证；新增字段可保留在存储中，不影响旧版本读取。回滚不会恢复已经由管理员关闭的 Web 登录权限，因此重新部署新版本后仍应检查这些密钥的开关状态。
