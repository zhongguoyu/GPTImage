# 双链路切换

管理员进入 **设置 → 基础配置 → 上游链路**，选择方案并点击“保存并切换”。无需重启。普通子账号无权修改。

- **ChatGPT2API 原生**：恢复原项目的账号池、调度器和各协议实现，包括网页文本、生图、编辑、搜索、模型和账号刷新；原项目按账号类型使用的 Codex 分支也保留。原生模式不使用专用 Sub2API 推理上游。
- **Sub2API 网关**：文本、Responses、Messages、模型、搜索、生成和编辑按统一上游补丁处理；不支持的旧网页功能仍明确报错。

无限画布继续调用 ChatGPT2API，随图片接口一起切换，无需更改画布地址。两种模式都保留新 UI、子账号业务额度和图片归档。原生模式会下载图片字节后归档，归档失败不会伪装成功。模型能力取决于所选上游，切换后请刷新生图页并在画布渠道重新读取模型；旧方案可能不支持另一方案的模型或工具。

## 配置优先级

选择保存于容器 `/app/data/routing-mode.json`（本地 Compose 对应 `runtime/chatgpt2api/data/routing-mode.json`），包含 `mode` 字段（`native` 或 `sub2api`）以及切换时间 `switched_at`。它优先于 `SUB2API_ONLY` 和图片配置是否存在。切回原生不会删除 Sub2API 地址、密钥或管理连接，切回网关会检查配置文件。

首次未保存开关时沿用环境配置，保持老部署兼容；本仓库 Compose 默认仍为 Sub2API。显式选择原生后，即使 `SUB2API_ONLY=1` 且 `IMAGE_UPSTREAM_CONFIG` 存在，也不会把图片提前交给 Sub2API。不要通过手工删除凭据切换方案。

## 切换边界

有 API 请求（含流式响应）或排队/运行中的图片、导出任务时，切换返回 409；等任务完成后重试。保存成功会清理文本缓存。未完成任务不要通过编辑运行文件强制切换；已失败的历史任务如需恢复，应选回创建时的方案。

当前保护针对仓库默认的**单进程 Uvicorn、单实例**部署；不要配置多 worker 或多副本热切换。外部上游可用性、账号授权及网页风控不由开关保证；接口失败不会自动回退另一条链路。账号池同步仍属于独立管理功能，保留其既有配置。

管理员接口：GET `/api/routing-mode` 查询当前模式；POST 同一路径传入 `{"mode":"native"}` 或 `{"mode":"sub2api"}`，均需要管理员认证。状态接口不返回上游密钥。

## 原生模式的客户端来源（2026-10-16 更新）

原生模式现采用 `basketikun/chatgpt2api` 的锁定网页客户端，commit `dc105e51bd486bd75c8ef4f74be4bc4724bdfc33`。原文件保存在 `services/original_web_backend.py`，`services/openai_backend_api.py` 的兼容子类保留 Sub2API 隔离开关和当前异常类型，使现有任务、调度与额度处理继续工作。

恢复原作者的浏览器指纹、账号读取、初始化、文本入口、图片请求和搜索/文件请求实现；没有覆盖前端、图库归档、子账号额度或无限画布部署。图片编辑的点选评论转换为包含图片序号和坐标的文字指令；画笔标注仍由已有预处理合成到参考图像像素。Codex 大图响应解析继续保留此前修复。

同服务器、同账号对照中，fork 客户端的刷新和首页返回挑战 403，原作者客户端返回 200，并实测生成、编辑和文本成功。这个结果支持整体客户端实现差异影响可用性，但没有单独证明某一个请求头就是唯一原因；不应再将先前失败单独归因于服务器出口。模型和风控仍可能随上游变化。


## 账户状态与额度随链路同步

保存链路时会自动刷新现有账号，界面报告同步成功和失败数量。同步期间不能再次切换；失败不会回退链路，可以在号池管理重试。账号刷新后台任务也受切换保护。

- 原生：显示 ChatGPT 实际返回的状态、生图剩余量和恢复时间。仅当 `image_gen.remaining` 有有效数值时确认生图额度；明确的 0 与“未提供”区别显示。
- Sub2API：显示匹配网关账号的状态、调度权限及 5 小时／7 天用量窗口。用量百分比不是剩余生图张数；上游未提供生图额度时显示“未知”。
- 账号信息记录来源和更新时间。切换后旧来源、旧切换周期及刷新失败的账号显示“待刷新”，不再累加旧额度或显示旧恢复时间。切回原来的方案也重新同步。
- 子账号业务额度是本站管理员设置的授权，不随上游切换重置；累计成功／失败记录保留。

切换 POST 返回 `account_refresh` 成功／失败计数，或同步失败说明，不返回账号凭据。单独账号同步失败不等于链路保存失败。


## 原生 image2.5

原生模式有账号时，模型列表也提供 `gpt-image-2.5-flare` 和 `gpt-image-2.5-sunburst`。生成、编辑的 prepare 与 conversation 请求均保留所选的完整模型名，不再映射为 auto；原有 gpt-image-2 配置映射继续保留。网页刷新生图页、无限画布重新读取渠道模型即可选择。上游账号权限仍可能限制具体模型。


## 重复额度快照与本地估算

上游反复返回相同额度（例如 1000）时，刷新不能清除本站已记录的生图扣减。独立 `native_quota_state` 保存上游快照、恢复时间和本地剩余量，切换到 Sub2API 不会删除它。原生重复刷新保留较小剩余量；只有上游明确增加或已到此前恢复时间才允许回升。扣减后展示“本地估算”，不代表官方精确剩余张数；缺少恢复信息时不会凭空按每日重置。已被旧实现覆盖的历史扣减无法仅凭当前值准确恢复。
